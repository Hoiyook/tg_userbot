## 2. 链路一：TG 媒体（主力链路）

### 2.1 数据流

```mermaid
sequenceDiagram
    participant U as 用户
    participant SM as 收藏夹
    participant L as listener_worker
    participant Q as download_tasks
    participant D as 下载worker
    participant V as V1磁盘
    participant CD as CD2至115

    U->>SM: 转发媒体（或白名单chat收到）
    Note over SM: 白名单媒体先记 listener_task（转发任务，SQLite 持久化）
    L->>SM: 受控转发副本进收藏夹
    L->>Q: 副本建 media 任务（write-through 落库）
    Q->>D: claim（租约）进 PROCESSING
    D->>D: 引用失效？先重取消息换新引用
    D->>V: iter_download 断点续传（.download 锚点）
    D->>D: 内容判重 sha256（落盘前）
    D->>V: os.replace 原子落盘
    D->>CD: CD2 监听目录自动备份上115
    D->>Q: COMPLETE，移除任务
```

### 2.2 关键机制

- **断点续传**：`.download` 半成品是**续传锚点**，重试/重投/重启都从断点继续；代理掐流只损失尾部。有字节推进时重试上限 3→15 次；零推进维持 3 次快速止损。
- **引用自愈**：`LocationInvalidError`/`FILE_REFERENCE_EXPIRED` 先重取消息换新引用再重试（连续 2 轮零字节或断点处连续 3 轮停滞 → 判定**媒体服务器端失效/截断**，移出队列并通知，不再无限重投）。
- **看门狗**：120s 无进度判连接僵死，取消重试。
- **半成品清理**：启动清理只动 **7 天以上**的陈旧 `.download`（新鲜锚点绝不动）。

### 2.3 命令

| 命令 | 作用 |
|------|------|
| `/queue` | 队列与待重试列表 |
| `/retry` / `/retry_all` / `/retry_del` | 重放/清空/移除待重试 |
| `/queue_del N` | 移除队列任务 |
| `/progress` | 进行中下载实时进度（含来源链接） |
| `/done` | 最近完成清单 |
| `/find <关键词>` | 按标题查一条媒体的下落 |
| `/thread N` | 调并发（1-15，每条占一条独立连接） |

## 3. 链路二：抖音/Instagram 单链接

```mermaid
flowchart TD
    A["收藏夹收到链接"] --> B{"本地 f2 解析"}
    B -- "成功" --> C["入队 url 任务，direct_url 就绪"]
    B -- "失败/超时" --> D["链接转第三方解析bot 兜底，永不丢"]
    C --> E["执行期：直链临期自动刷新，签名只活3小时"]

    D --> I["bot 回复视频，白名单流自动下载"]
```

- **双保险降级**：本地解析失败自动转 `@DouYintg_bot`（它在自己服务端解析，不受本地风控影响），回复的视频经白名单流自动下载——**最坏情况 = 维持日常可用**。
- **HTML 守卫**：下载流拿到 `text/html` 一律判失败重试，**绝不落盘假文件**。
- cookie 更新：`/cookie`（或 bot 菜单 ✏️ 更新）。

## 4. 链路三：抖音作者批量 `/dyu`

### 4.1 全流程

```mermaid
flowchart TD
    A["/dyu 主页链接 可选子目录"] --> B["Chrome DOM 收割：Agent真Chrome开作者页，注入登录态，容器滚动"]
    B -- "失败" --> C["f2 游标翻页枚举，403 三档退避 15/30/60s"]
    B -- "验证码" --> B1["页面保留加通知，手动滑一次后重发"]
    B -- "成功" --> D["作品清单"]
    C --> D
    D --> E{"逐条 dyc 判重"}
    E -- "已下载" --> F["跳过"]
    E -- "新" --> G["入队 serial url 任务"]
    G --> H["串行执行 20秒/条"]
    H --> I["转解析bot，盖在途目录戳"]
    I --> J["bot回流视频走白名单流，目录戳消费，落 抖音/子目录"]
    H --> K["f2 直连解析下载，cookie 自动保鲜"]
    K -- "成功" --> L["直连下载落 抖音/子目录"]
    H --> M["多次未成按退避重试，无上限"]
```

### 4.2 状态流转（每条作品的任务）

```mermaid
stateDiagram-v2
    [*] --> PENDING: 入队（dyc判重通过）
    PENDING --> PROCESSING: claim加租约（attempts加1）
    PROCESSING --> PROCESSING: 每轮转解析bot（任务保留等回流）
    PROCESSING --> SETTLED: bot回流视频，销账出榜
    PROCESSING --> SUCCESS: f2直连下载完成
    PROCESSING --> PENDING: 都失败退避（60s起指数，无上限）
    SETTLED --> [*]
```

### 4.3 命令与注意

| 命令 | 作用 |
|------|------|
| `/dyu <链接> [子目录]` | 发起批量（子目录省略用作者昵称） |
| `/dyu <链接> since YYYY-MM-DD [子目录]` | **只要该日期之后的作品**（f2 枚举+整页早停；v1.1） |
| `/dyu <链接> all [子目录]` | **连转发的也收**（默认仅原创；v1.2） |
| `/dyu` | **进度面板**（待下载/下载中/待重试/最近完成） |

- **默认仅原创**（v1.2）：作品列表里的转发内容自动跳过（判据=作品
  author.sec_uid 是否为作者本人，实测可靠）。要连转发一起收加 `all`。
  原创/起止日期过滤都走 f2 枚举（Chrome 页面读不到这些字段）。
- **节流 20s/条**是硬约束（保护第三方 bot），87 条全量约 30 分钟转交完。
- **在途目录戳**：转交瞬间盖章，bot 回流的下一个视频落 `抖音/<子目录>/`（一次性消费，180s TTL）。偶发错位（bot 乱序回复）会把某条落进默认目录，手动移动即可。
- 触发**验证码**：bot 会把验证页留在 Chrome 窗口并通知，手动滑一次、重发命令。
- ~~msToken 保鲜~~ 已退役（v1.4）：新版抖音不再落持久 cookie，枚举主路为 Chrome 钩子收割，不依赖 msToken。

## 5. 链路四：Pawchive（`/paw`）

```mermaid
flowchart LR
    A["paw plan 作者"] --> B["扫描 API 分页"]
    B --> C[("pawchive_posts/files")]
    C --> D["worker 8帖并发"]
    D --> E["死链预检 404/410 快速失败"]
    E --> F["httpx 下载 .part 断点续传"]
    F -- "429" --> G["等60s 不烧重试额度，12次硬上限"]
    F -- "成功" --> H["串行解压 zip/rar"]
    H --> I["全DONE无外链则COMPLETED；有外链则MANUAL通知"]
```

- 常用：`/paw`（状态）/ `/paw plan <作者>` / `/paw retry <id|all>`（死链不重投）/ `/paw manual`（外链清单）/ `/paw pause|resume` / `/paw csv <作者>`。
- **外链白名单**（v1.3）：帖子里的站外链接只有命中常用网盘（MEGA/
  Google Drive/百度/夸克/阿里云盘/蓝奏云/PixelDrain/GoFile 等）才记录并
  可能进人工清单；社媒/个人站等噪声链接直接丢弃——仅含噪声链接的帖子
  整体不入队。白名单在 `config.PAWCHIVE_EXT_LINK_HOSTS`，可扩。
- 缩略图追回：`/paw recoverthumbs on`（死链补低清缩略图）。
- 磁盘保护线 2GB：低于暂停 worker，`/paw resume` 恢复。

## 6. 链路五~七：Chrome 直链 / 115 解压回传 / 种子离线

### 6.1 `/chrome [子目录/][#标注] URL`
网盘页等浏览器才能下的直链交给 Chrome Agent（独立实例可后台）。`/chrome_tasks` 看任务（每条带 🛑 取消），`/chrome_start|stop|status` 管 Agent。

### 6.2 `/115x <115路径>`（递归含子目录）
```mermaid
flowchart TD
    A["115x 云下载"] --> B["BFS 递归扫描 gRPC 视角，深度8目录400上限"]
    B --> C[("extract_tasks")]
    C --> D["1 拷贝到本地staging，同尺寸跳过即幂等"]
    D --> E["2 解压 zip/rar/7z，加密终结，炸弹拒"]
    E --> F["3 逐文件回传到 115原目录/包名"]
    F --> G["4 对账：gRPC 逐目录尺寸 加 CD2任务清空 双保险"]
    G -- "一致" --> H["COMPLETED 清 staging"]
    G -- "不符" --> I["FAILED 差异清单 退避"]
```
- 回传目标 `<原目录>/<压缩包名>/` 天然防同名、防套娃。
- `.zip` 结尾的**目录**是 115 云解压残留（不是压缩包），扫描会提示跳过。
- `/115x` 裸命令看状态；`stop/start/retry id/del id`。
- `/115x watch <路径>`：**登记目录每小时自动扫新包入队**（v1.6，唯一键判重只收新的；`/115x watch` 看列表，`unwatch <路径>` 取消；登记持久化跨重启）。
- **加密压缩包**（v1.7）：需密码时自动用**压缩包所在最后一层目录名**做密码尝试一次（如 `/云下载/Telegram@XXX` 下的包用 `Telegram@XXX`）；仍失败则跳过（PASSWORD 状态，不占队列），下次扫描该目录时自动重置再试。支持 ZipCrypto/AES（libarchive）。
- 依赖：CD2 运行中 + 挂载 `/Volumes/CloudDrive` 在线。

### 6.3 种子/磁力（全自动）
收藏夹或 bot 对话发 `.torrent` 链接/文件 → 解析 infohash → 115 离线 → **完成守望**轮询目录，新文件出现即通知（默认守望 30 分钟）。`/cd2tasks` 看离线/上传任务。

## 7. 数据不丢：五层保障

```mermaid
flowchart TD
    A["保障总览"] --> B["1 全任务 SQLite write-through，入队即落库"]
    A --> C["2 租约加崩溃自愈，启动恢复过期 PROCESSING"]
    A --> D["3 指数退避自动重放，60s 扫描到期任务"]
    A --> E["4 断点续传锚点，.download/.part 跨重启续用"]
    A --> F["5 消息不静默丢失，启动补拉加 pts 缺口看门狗"]
    B --> G["关机/重启后任务自动续跑，已下载的凭判重不重下"]
    C --> G
    D --> G
    E --> G
    F --> G
```

| 场景 | 行为 |
|------|------|
| 下载中关机 | 半成品留锚点，重启续传（不重下已完成字节） |
| 消息在停机窗口发来 | 启动 catch_up 补拉（日志「📬 启动补拉完成」） |
| 连接活着但更新流卡死 | pts 看门狗检测缺口 → 补拉 → 两次无效断开重连 |
| worker 崩溃 | 租约到期自动回 PENDING 重跑 |
| DB 暂时写失败 | 任务不推进状态，下轮重来（绝不假成功） |
| CD2 备份 | **搬移语义**：上传 115 后删本地源（本地是暂存区，115 是归档） |

## 8. 数据不重：判重体系

```mermaid
flowchart TD
    A["新任务/新消息"] --> B{"元数据判重 tg: f: dyc:"}
    B -- "命中" --> Z1["跳过（已下载索引加在途队列两级）"]
    B -- "未命中" --> C["下载至临时文件"]
    C --> D{"内容判重 c:sha256 落盘前"}
    D -- "字节相同" --> Z2["丢弃临时文件按成功收尾"]
    D -- "不同" --> E["原子落盘加记入索引"]
    F["任务表唯一索引"] --> G["重复扫描不产生重复任务"]
```

- 原则：**不确定就放行**（判重永不误拦，宁可重复下载一条也不丢）。
- `/dedup on|off` 可临时关闭（关闭后同内容会重复落盘，慎用）。
- 终结性任务（媒体失效/死链/需密码）**移出队列不再重投**，避免无限空转；`/paw retry` 与 `/dyu retry` 可人工重投。

### 注意事项（踩过的坑）

1. **代理是命门**：TG 全部流量走 `tg_proxy`（Hiddify）；代理劣化表现为下载反复断流、`IncompleteReadError`——换节点即可，链路自愈。
2. **抖音风控三件套**：403（msToken 过期，等冷却或刷新 Chrome）、验证码（Chrome 窗口手动滑）、游客墙（Chrome 收割自动注入登录态）。
3. **CD2 必须在跑**：`/115x`、备份、对账都依赖；掉线时相关任务退避等待，不丢。
   ⚠️ **FUSE 挂载会单独死**（2026-10-19 实测）：CD2 进程活着、gRPC 正常，但
   挂载整体 `Device not configured`——表现为 /115x 全部「挂载视图抖动」。
   处置：重启 CD2（自动重新挂载）即可恢复；重启后 TERMINAL 的任务重投即成
   （gRPC 视角文件一直在，死的只是挂载视图）。
4. **`/dyu` 大作者耗时长**：串行+20s 节流是刻意设计（保护第三方 bot），别并行。
5. **判重键清理要谨慎**：`dyc:`/`c:` 键删除后可能重复下载；只在确知污染时清。
6. **敏感信息**：cookie/token 只存 `tg_secrets.json`（gitignore），绝不入代码/日志。

## 11. 本地 API 入队（套壳 app / 手机看板，2026-11-01）

userbot 进程内的只读+薄写入 HTTP 服务（aiohttp，随主进程启停）。**与 bot 菜单读写同一套状态**——看板看到的队列/台账与 `/queue`、`/stats` 同源，不建第二套状态。

**开启**（`tg_secrets.json` 的 `api` 段，重启生效）：

```json
"api": {"enabled": true, "bind": "127.0.0.1", "port": 8765, "token": "随机长串"}
```

- `bind=127.0.0.1` 且 token 留空 = 仅本机免鉴权；**非 loopback 必须配 token，否则拒绝启动**。手机访问：同 WiFi 绑局域网地址，外网推荐 Tailscale（两端装，app 填 Tailscale IP）。
- 鉴权三通道任选：`Authorization: Bearer <token>` / `X-Token` 头 / `?token=` 查询参数。

**端点**：

| 端点 | 说明 |
|---|---|
| `GET /` | 看板页面（总览/队列/入队/历史，2s 轮询） |
| `GET /api/status` | 总览快照：在途/排队/待重试/今日台账（rebuild 口径）+ 在途进度 + 磁盘余量 |
| `POST /api/enqueue` `{"text": "…"}` | **与往收藏夹发这条消息同语义**：抖音/IG → 本地解析入队（失败转解析 bot）→ 种子 → 115 离线 → B站 → 外链台账；分享文本里的非链接部分自动当备注 |

share_target（/share 分享接收页）。手机浏览器打开 ts.net → 「添加到主屏幕」

的独有价值只剩离线补投，可退役。SW 只缓存静态壳（/api/* 永远网络优先）；
manifest/sw/图标/share 页免鉴权可取（安装与分享面板不带令牌）。

**访问面（2026-11-01 收紧后）**：API 只绑 `127.0.0.1`——局域网/Tailscale 网卡均不可达，
唯一公网入口 = Funnel 的 `https://<节点>.ts.net`（TLS + token）；**非 loopback 来源
限流 120 次/分钟**（429），本机豁免。

**Telegram 中转通道（v2.1，解决"安卓单 VPN"限制）**：手机上 Tailscale 与代理
（Hiddify 等 VPN 模式）互斥，套壳 app 的分享改为**持 bot token 经 Bot API**
以 bot 身份把「🛰 <原文>」发进 bot 对话；主账号在 `new_message_handler`
入口（classify 之前）识别 bot 发来的 🛰 消息 → `api_server.handle_app_relay`
→ 与 `/api/enqueue` 同一条 `dispatch_link_text` 链路 → 结果以「📲 分享直达」
通知回控制面板。app 端 fire-and-forget；标记 🛰 不在 CLEAN_NOTIFICATION_PREFIXES
（单测钉死，防 bot 通知被误当分享）。**手机零新增依赖**：Telegram 能通它就能通，
代理照常用，Tailscale 留在 Mac 侧即可。

**远程看板：Tailscale Funnel（2026-11-01）**：`tailscale funnel --bg 8765`
把 API 发布为 `https://<节点名>.<tailnet>.ts.net`（首次需在管理页一键授权，
链接由命令输出给出；TLS 证书自动签）。手机不装 VPN——浏览器直接开
`https://…ts.net/?token=<api token>` 即仪表盘，或把该域名填进 app
「服务器直连」。关闭：`tailscale funnel --https=443 off`。该地址公网可达，
仅靠 api.token 保护。

**套壳 app**（`prototype/NagramShell/`，Kotlin+Compose，<500 行）：WebView 载看板（地址+token 首次配置）+ 系统分享直达（分享面板「存到下载器」→ POST 入队）+ **离线补投**（后端不可达时分享内容暂存本机，可达后自动重投；服务端三级判重兜住重复）。通知不走 app——仍由 Telegram 控制面板承担。
