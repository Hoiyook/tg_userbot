# TG Userbot 指令手册（全量版）

> 生成：2026-10-26，依据当前代码全量盘点（commands.py 分发器 + 各功能模块 parse/USAGE + BOT_COMMANDS 注册表逐条核对）。
> 指令在 **Saved Messages（收藏夹，发给自己）** 与 **bot 私聊对话** 都可执行（owner-only，仅本人账号有效）。
> 发任意文本给 bot = 打开按钮菜单；`/start` 同效。

## 〇、通用约定（先读这段）

1. **下划线标准形 / 空格兼容形**：多词指令两种写法等效——`/paw_plan 作者` 与 `/paw plan 作者`、`/listen_add …` 与 `/listen add …`。入口自动把空格形改写为下划线形。适用家族：`/paw` `/listen` `/wl` `/retry` `/queue` `/sqlt` `/cmdt` `/caption_filter` `/115x` `/wnacg` `/115dup` `/115inv`。
2. **快捷指令**：发 `1`（非 / 开头）= `/cmdhis`（映射表 `config.COMMAND_SHORTCUTS`）。
3. **裸命令 = 状态视图**：绝大多数指令不带参数时显示当前状态/进度（如 `/paw`、`/dyu`、`/x`、`/115x`、`/wnacg`、`/115dup`、`/115inv`）。
4. **回复格式**：多行回复自动代码块化（可整块复制）；指令回复会被自动清理，媒体与用户内容永不删。
5. **owner-only**：全部指令仅本人可触发；白名单聊天里发的消息永远不触发命令。
6. **`|` 表示任选其一，`[]` 表示可选参数，`<>` 表示必填参数**（下文语法沿用）。

## 二、下载队列与并发

### /queue 族

```
/queue               活跃下载队列（分页 10 条/页，序号为全局序号）
/queue_del <序号>     移除任务（= /queue del 序号）；执行中的任务会先真正取消在途下载（清 .download 半成品、归还连接）再移除
```

### /retry 族

```
/retry               待重试列表（分页 10 条/页；失败原因 + 原帖跳转链接 + ✅ 执行按钮）
/retry <序号>         单条立即重放（不看退避、无次数上限）
/retry all           重放全部待重试（执行中的跳过）——标准形 /retry_all
/retry del <序号>     从待重试列表移除——标准形 /retry_del
```
后台机制：失败任务按退避（60s 起指数、封顶 30min）自动重放，最多 10 次；超限只能手动救。

### /thread — 并发下载路数

```
/thread          查看当前并发数
/thread 10       设置并发（有效范围 1-25；每路一条独立连接，n 路 ≈ n 倍单路速度；持久化、即时生效）
```

### /dedup — 重复媒体去重

```
/dedup           查看状态与索引条数
/dedup off       关闭（想重新下载已删文件时用）
/dedup on        重新开启
```
四层判重：`tg:` 文件ID / `dyc:` 抖音作品ID / `f:` 文件名+大小 / `c:` 内容 SHA256。

## 四、标签监听 /listen

> 与下载白名单完全独立：按周期主动扫描指定聊天，命中 `#标签` 后转发目标并按需下载。配置身份只认 chat id。首启不扫历史（从添加时刻起）。

```
/listen                                    状态 + 规则列表 + 任务存量 + 评论跟进条数
/listen on ｜ /listen off                   总开关（立即生效并持久化）
/listen scan                               立即扫描一轮（不等周期）
/listen interval <分钟>                     扫描周期（1-10080，默认 1440=每天）
/listen add <聊天> <标签> [目标,目标] [on|off]
/listen del <序号>                           删除规则
/listen failed                              失败任务明细（最近 15 条，含 #行id）
/listen retry <行id>                         失败任务重试 ——⚠ 当前版本解析缺陷：带参数会被丢弃，建议用 bot 菜单
/listen history <聊天> <标签>                整频道从第一条回扫该标签（断点续扫、幂等判重）
```

**添加示例**：
```
/listen add @speedlearnnn #测试标签 me,@某个频道 on
```
- 聊天：`@用户名` 或数字 ID；标签必须 `#` 开头（如 `#01musume`）。
- 目标：`me`（收藏夹）/ `@用户名` / 数字 ID，逗号分隔多个；**省略则只转发收藏夹**。
- 末尾 `on/off` = 是否自动下载（省略 = off 只转发不下载）。
- `download=true` 隐含收藏夹目标；落盘目录按转发副本的真实来源（监听聚合频道时文件落原帖目录）。
- `/listen edit <序号>`：文本形当前未实现，**修改走 bot 菜单「✏️ 修改」**（多步向导）。

## 七、Chrome 下载（/chrome 族）

> Agent 驱动一台**专用独立 Chrome 实例**（无头、独立 Profile、不带登录态）下载直链，落 `下载目录/TG Chrome Download/[子目录]/`。

```
/chrome_start                       启动 Agent（幂等；显示 Chrome 路径/版本/下载目录）
/chrome_stop                        停止 Agent（专用 Chrome 保持运行）
/chrome_status                      Agent/Chrome/CDP 状态 + 任务统计 + 待入队请求 + 最近完成
/chrome_tasks                       列可取消任务（进行中→排队→等待重试；每行含短 ID）
/chrome_cancel <序号|任务ID前缀>      取消任务（ID ≥6 位十六进制不受序号漂移影响；在途的真正中止 Chrome 下载并清半成品）
/chrome [目录/][#标注] <URL>          提交 URL 下载任务
```

**/chrome 语法细则**（URL 恒为最后一个参数；它前面那个 token 是「目录+标注」）：

```
/chrome https://example.com/a.zip              直链 → 直接下载
/chrome #标 https://a.com/t.zip                文件名加标注 #标
/chrome A/B/#标 https://a.com/t.zip            落 TG Chrome Download/A/B/，文件名带 #标
/chrome Hyuk/250630 https://a.com/t.zip        纯目录（token 不带 # = 整体是目录）
```
- URL 只支持 http/https；子目录拒绝 `..` 穿越，非法退回根目录。
- **网盘链接自动分流**（mega/Google Drive/OneDrive/百度盘/夸克/115/123 等）：不进下载流，改为在**日常 Chrome** 可见打开（带登录态，文件落 Chrome 默认下载目录）。
- 结果自动通知（文件名/大小/目录）；取消/失败同样通知。
- bot 对话里直接发 iwara 视频链接 = 自动转 `/chrome <URL>`。

### /wnacg — 漫画 → 115 漫画目录 → 自动解压

```
/wnacg <地址|aid> [作者]        入队下载。地址支持 photos-index-aid-N.html / download-index-aid-N.html / 裸 aid
/wnacg                          队列状态（最近 15 条，含阶段与错误）
```

## 十、115 运维（查重 / 清单 / 对账 / 报告）

### /115dup — 全盘查重（SHA1 判重，不读文件内容）

```
/115dup scan [路径] [分钟]          启动后台扫描（默认全盘 /115open，时限默认 10 分钟、上限 1440；参数顺序不拘）

/115dup show <组号>                组内全路径明细（含写入时间与 SHA1）
/115dup del <组号> [keep=oldest|newest] [确认]    删重复（默认 dry-run 预览；加「确认」才真删；删除=115回收站可恢复）
/115dup report [115目录]           导出报告 TXT+CSV → 传 115 /115open/userBot报告/日期/ → 尺寸对账
/115dup apply <csv路径> [确认] [全组]   按审表 CSV 批量执行删除/移动/重命名（见下）
```
示例：`/115dup scan 30`、`/115dup scan /115open/视频 20`、`/115dup del 5 keep=newest 确认`、`/115dup apply /115open/userBot报告/2026-10-24/查重报告_xxx.csv 确认`

**apply 审表语义**：在 /115dup report 的 CSV（utf-8-sig，Excel 可编辑）上——`deleted` 列填 1/true/是 = 删该份（回收站）；「新目录」列填了 = 移动；「新文件名」列填了 = 重命名；都留空 = 不动。先 dry-run 出计划，加 `确认` 执行（分钟级转后台，中断可重发同命令续跑，已执行行自动跳过）；同组全员标删须额外加 `全组`。执行结果回写 `*_执行结果_*.csv` 并传回 115 同目录。硬约束：删除只进回收站、绝不覆盖同名、逐行 SHA1 校验身份、事后终态核验。

## 十二、Caption 命名清洗 /caption_filter

> 转发说明常带结构化字段与 URL，本功能按规则把它们从**文件名**里清掉（只影响命名，不动消息）。

```
/caption_filter                          规则列表
/caption_filter add <规则>                添加规则（实时生效、重启仍在）
/caption_filter del <序号>                 删除
/caption_filter clear                     清空全部
/caption_filter reset                     恢复默认 7 条
/caption_filter test <原文>                用真正的清洗逻辑试跑一段文本
```
**四类规则**（前缀只切第一个冒号）：
- `exact:<串>` 删这个确切子串；`contains:<串>` 删所有出现（宽匹配）；
- `regex:<正则>` 按正则删（非法正则跳过）；`field:<字段名>` **剥标签留值**（`作者：#腿玩年` → `#腿玩年`）。
- 执行顺序恒为 field → exact → contains → regex → 空白归一。
- 默认规则：`field:作者`、`field:期数`、`field:角色`、`field:i站地址`、`field:标签`、`regex:https?://\S+`、`regex:【.*?】`。
- 示例：`/caption_filter_add field:来源`；`/caption_filter_test 作者：#腿玩年 期数：bl11` → `#腿玩年 bl11`。
